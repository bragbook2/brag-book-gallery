=== BRAGBook Gallery Changelog ===

= 4.9.3-beta7 (2026-08-18) =

Added:
* The procedure filter narrows a provider page's heading - the procedure-mode dropdown now writes the chosen procedure into .brag-book-gallery-content-title, reading the heading's own emphasised text as the base so nothing has to be passed in and both archive layouts, tiles and sidebar, are covered by the one element. Reset and the All Procedures option restore it. The provider-mode dropdown leaves the heading alone

= 4.9.3-beta6 (2026-08-18) =

Added:
* A provider can be named on the gallery shortcode - [brag_book_gallery provider="dr-jane-smith"] takes the providers taxonomy slug and [brag_book_gallery provider_id="43"] the API ID the plugin's other provider attributes take. Either resolves to the context the archive builds, through one method both now share, so the page gets the archive's structure whole: the procedures and filters dropdowns, the provider-scoped grid and its Load More, and data-provider-slug/data-provider-id on the wrapper that the referrer capture reads to keep a case's next and previous inside that provider. Resolution runs after the single-case checks, so a case URL still opens its case
* Provider label settings - two text fields under Enable Providers hold the practice's wording for a provider, singular and plural, and Provider_Filter::render_filter() takes every string it shows from them: the toggle and its data-default-label, the search placeholder and aria-label, the listbox label, the All option, the no-match line and the localized emptyLabel. The plural is stored separately rather than derived, since the plural of "Doctor or Provider" is not the singular with an s. Settings_Helper::get_provider_label() and get_provider_label_plural() fall back to Provider and Providers on a blank field

Fixed:
* The GoHighLevel form height field refused every save - a stored 0 rendered as value="0" against min="200", so constraint validation blocked the form even with the built-in source selected. 0 means "use the default 700", so it renders blank, and min/max are only emitted while gohighlevel is the saved source. save_settings() still clamps a supplied height to 200-2000
* Assets shipped under a stale cache-busting version - Assets::get_asset_version() returned a hand-maintained constant left at 4.6.0-beta4, so every CSS and JS rebuild since went out under the same ?ver= and browsers kept the copy they had, the V2 thumbnail-strip fix included. The frontend and admin enqueues now pass their asset path through Asset_Manager::get_asset_version(), which versions by filemtime, and the unused constant is gone
* The thumbnail-strip offset applied to V3 cards, whose overlay sits in flow beneath the image with nothing to clear. The rule is now scoped to cards that are not V3

= 4.9.3-beta5 (2026-08-17) =

Added:
* A GoHighLevel form can replace the built-in consultation form - a Consultation form choice under the consultation toggle switches between the two, with fields for the form's address and the height it opens at. The embed only stands in once an address is given, so choosing GoHighLevel with an empty field keeps the built-in form serving requests. GoHighLevel's form_embed.js is enqueued alongside it to resize the frame to the form's own height. All three consultation dialogs render through one method. Requests through the embed go straight to GoHighLevel: the plugin neither stores nor emails them
* Case counts in the provider archive's procedure filter, tallied from the case/term pairings for that provider's cases rather than read from the term's own count, which covers the whole library

Changed:
* The gallery filter bar is hidden on a case opened from a provider; a case reached from a procedure, or directly, keeps it

Fixed:
* The V2 hover panel covered the thumbnail strip and took the provider name and arrow with it. It now ends where the strip begins, and the strip stacks above it so thumbnails stay clickable while the panel shows
* Thumbnails centre in their strip rather than starting hard left, with safe centring so the first stays reachable once the strip scrolls

= 4.9.3-beta4 (2026-08-14) =

Added:
* Carousel navigation choice on V2/V3 cards - alongside the dots over the image, cases can show a thumbnail strip between the image and the card's title bar with an arrow either side. Arrows step from wherever the carousel currently sits, a thumbnail selects its slide outright, and the strip scrolls rather than shrinking when a case has more photos than fit. Thumbnails take the small rendition through the shared variant lookup, falling back to the full-size URL where no variant exists, and a 1px rgb(0 0 0 / .1) rule divides the strip from the title beneath it. The setting is nested under the carousel toggle it depends on and greyed out while that toggle is off

Fixed:
* The Delete All Synced Data dialog clipped its buttons - the shared dialog is capped at 24rem, sized for a sentence and two buttons, while this one carries a list, a confirmation field, a progress bar and up to three buttons, so the footer ran past the edge and the last button was cut off by the content's overflow. It now sizes to 34rem with a wrapping footer, and the warning and trash glyphs are gone along with the script that swapped between them

Changed:
* The radio-and-description layout used by the nudity presets is shared under one class rather than copied, now that a second setting uses it

= 4.9.3-beta3 (2026-08-14) =

Changed:
* The referrer records the provider's member id alongside the slug - only the provider-scoped procedures grid ever rendered an id for the script to read, so provider-id was always null. The slug is what the adjacency endpoint prefers, so navigation worked, but nothing was left to fall back on if a slug stopped resolving to a term. Both provider archive layouts and every provider dropdown option now carry data-provider-id, and the script reads whichever it finds. The id comes from a single Taxonomies::provider_member_id() resolver (provider_id, falling back to provider_member_id) that the queried-archive lookup now shares

= 4.9.3-beta2 (2026-08-14) =

Fixed:
* The referrer capture missed a whole card style - the click handler that records which gallery a case was opened from matched only .brag-book-gallery-case-card-link and .brag-book-gallery-case-permalink. The permalink is emitted on default cards and on v2/v3 cards with a carousel, but a single-image v3 card carries only .brag-book-gallery-case-card-overlay-button, and the whole-card fallback checks for the same two classes before it acts. On those cards nothing was recorded, so the case page kept its server-rendered procedure links and provider navigation looked broken while working on sites whose cases have carousels. All three anchors now come from one selector

= 4.9.3-beta1 (2026-08-14) =

Fixed:
* Provider slugs came back with the member id after a sync - 4.9.2 added a name-only slug builder but wired it into one of the six places that create or rename a provider term, and not the chunked sync, which is the path a full sync runs, so every sync rebuilt {name}-{member id} however many times the migration had shortened it. The builder moved to Taxonomies::provider_term_slug() and all six call sites use it
* The slug migration matched against the whole old {name}-{member id} form, so a provider renamed since their term was created kept the id. It now shortens any slug ending in -{member id}, still skipping hand-edited slugs and names whose shortened form is taken, and re-runs on sites where it has already run
* Provider terms are no longer created with "Provider profile for provider ID 4" as their description, which the provider's page renders under the heading. Existing placeholders are cleared by the same clean-up, matched on the exact generated wording so a description written by hand survives

= 4.9.2 (2026-08-13) =

Stable release of the 4.9.2 line. The beta entries below carry the detail.

Added:
* Provider pages - a term archive at /providers/{provider}/ rendering through the gallery and following the Procedures View setting, plus a /providers/ page listing every provider with profile photo and case count from the new [brag_book_gallery_providers] shortcode. A provider's name on a case links to their page, preferring it over the API profile URL
* A procedure filter on provider archives, in place of the gallery picker, scoping a provider's grid to one procedure
* Context-aware previous/next on cases: arriving from a provider page or filter walks that provider's cases and wraps at both ends; arriving from a procedure keeps procedure navigation
* Responsive image variants across the grid, carousels, favourites, the case detail viewer and related cases, with narrow screens pointed directly at the smaller renditions
* Configurable nudity warning - title, body, button label, decline link and destination, three presets, and a reset control
* randomize="true" on [brag_book_gallery_procedures], seeded per page load so Load More continues the same shuffled order

Changed:
* Provider slugs drop the API member id: /providers/dr-mi-payne/ rather than /providers/dr-mi-payne-8/. Terms synced earlier are renamed once, leaving hand-edited and colliding slugs alone; old URLs are not redirected
* Load More paginates within the active view - provider, location and procedure - through the same ordered result set as the initial render
* Delete All Synced Data runs in batches with progress reporting
* Roughly 1,850 lines of unreachable frontend JavaScript removed

Fixed:
* Carousel touch scrolling, duplicate cases across procedure categories, the single-letter SEO title and meta description, and the provider page issues found through the beta line: the 404, the displaced first card, the stray block-theme paragraphs, and navigation that ignored the provider on SEO-slugged sites or on any layout other than tiles

Security:
* The API token is no longer localised into the page source, and rate limiting works again on the consultation form, the favorites email lookup and the API client. Rotate the token if the site has been public

= 4.9.2-beta9 (2026-08-12) =

Fixed:
* Referrer-based previous/next navigation never ran on sites whose cases use SEO slugs - initializeProcedureReferrerTracking() identified a case page by a path ending in digits, but generate_case_slug() uses the API's seoInfo.slug whenever the account supplies one and only falls back to the numeric case id when it does not. On those sites the referrer was written when a card was clicked and never read on the case page, so the arrows kept their server-rendered procedure links, affecting procedure combo navigation and the new provider navigation alike. The page is now recognised by the .brag-book-gallery-case-detail-view element that both the default and alternative case views render, with the digit match kept as a fallback

= 4.9.2-beta8 (2026-08-12) =

Added:
* Decline option on the nudity warning - the full-screen (Global preset) warning now renders a decline link beside Proceed that sends the visitor to a configurable URL, defaulting to the site home page; the link text and destination are set in Nudity Warning Settings on the General settings page. The link is Global-only: the per-card overlays cover a single case rather than the page, so navigating the browser away from one would not match what was clicked
* Reset Nudity Settings button - clears the preset and every copy field, restoring the plugin defaults (the defaults are resolved at render time, so deleting the stored values restores them)
* Procedure filter on provider archives - the "Choose a Gallery" picker is hidden there, since it navigates away to another procedure, and a procedure filter takes its place listing the procedures that provider has cases in; it reuses the provider filter's component, so it is organised like the gallery picker and styled like the Filters dropdown, and is skipped when fewer than two procedures remain
* Provider-scoped case navigation - arriving at a case from a provider page walks the previous/next arrows through that provider's cases instead of the procedure's, and wraps, so the last case leads back to the first and the first back to the last; a procedure chosen in the new filter narrows that to the provider's cases in that procedure. Arriving from a procedure page is unchanged, hard ends included
* randomize attribute on [brag_book_gallery_procedures] - randomize="true" shuffles the cases on every page load instead of using the curated order. The shuffle is seeded per page load and the seed travels with the Load More button, so later pages continue the same shuffled list rather than re-drawing and repeating or skipping cases; location searches keep their nearest-first ordering

Fixed:
* Provider archive grid dropped its first card - get_the_block_template_html() runs do_shortcode() over a block template's raw markup before do_blocks(), so the core/shortcode block held the expanded gallery HTML by the time it ran wpautop() over it, closing a paragraph at the first blank line and leaving an empty <p> as the grid's first child. That paragraph took the first grid cell, so the first card appeared to be missing and every card after it sat one cell further on with the paragraph's margins showing as extra space; the template now uses a core/html block, which passes its content through untouched

Note: this file was not maintained between 4.6.0-beta4 and 4.9.2-beta8. See readme.txt or CHANGELOG.md for the releases in between.

Fixed:
